# 🚀 Whisper Service v2 — Анализ и Рекомендации

## 📊 Проблема текущего сервиса

**Текущий стек:** `openai/whisper-large-v3-turbo` → PyTorch CPU → FastAPI

| Метрика | Текущий результат |
|---|---|
| Аудио 5–15 сек | 30+ секунд обработки |
| RTF (real-time factor) | ~2–6x (в 2–6 раз медленнее реального времени) |
| Причина | PyTorch CPU без INT8-квантизации, Python GIL, нет VAD |

**Корень проблемы:** PyTorch на CPU работает в FP32 без оптимизаций. Полный аудио-файл целиком скармливается модели, включая тишину и паузы.

## 🔬 Сравнение альтернатив

### Вариант A — `faster-whisper` (CTranslate2)

> Самый простой и быстрый путь к улучшению **без смены API**

| Параметр | Значение |
|---|---|
| Движок | CTranslate2 (C++) вместо PyTorch |
| Квантизация | INT8 — модель в 4x меньше весит |
| Ускорение vs текущего | **3–5x** (30с → 6–10с) |
| Многопоточность | ✅ `num_workers` параметр |
| Мультиязычность | ✅ все языки Whisper |
| Перевод | ✅ `task="translate"` |
| Offline punctuation | ❌ нет (только то что Whisper выдаёт) |
| VAD / удаление тишины | ⚠️ встроенный базовый `vad_filter=True` |
| Изменение клиентского кода | ❌ не нужно (тот же HTTP API) |
| Размер образа | ~3–4 GB (модель large-v3-turbo INT8) |

**Вывод:** Быстрый выигрыш. Рекомендуется как **первый шаг**.

---

### Вариант B — `sherpa-onnx` + SenseVoice + VAD + Punctuation

> Самый быстрый CPU-вариант. Полностью в Node.js, нативные потоки.

| Параметр | Значение |
|---|---|
| Движок | ONNX Runtime (C++), Node.js native addon |
| ASR модель | SenseVoice-small (Alibaba) |
| Ускорение vs текущего | **10–20x** (30с → 1.5–3с) |
| Многопоточность | ✅ нативные C++ потоки, не блокирует event loop |
| Мультиязычность | ✅ RU, EN, ZH, JP, KO и 50+ языков |
| Перевод | ❌ только распознавание |
| Offline punctuation | ✅ CT-Transformer модель (встроена в sherpa-onnx) |
| VAD / удаление тишины | ✅ Silero VAD встроен (убирает паузы ДО inference) |
| Изменение клиентского кода | ⚠️ нужно — новый порт/эндпоинт |
| Размер модели SenseVoice | ~250 MB (tiny!) |
| Размер пунктуационной модели | ~100 MB |
| Размер VAD модели (Silero) | ~2 MB |

**Вывод:** Идеально для голосовых сообщений. SenseVoice специально обучен на
разговорной речи, поддерживает эмоции и шумы. Самый маленький образ!

### Вариант D — `sherpa-onnx` + Whisper ONNX + VAD + Punctuation (гибрид)

> Максимальное качество + хорошая скорость + полный фичесет

| Параметр | Значение |
|---|---|
| ASR | Whisper-large-v3-turbo через ONNX Runtime |
| Ускорение vs текущего | **4–7x** (VAD убирает тишину + ONNX быстрее PyTorch) |
| Offline punctuation | ✅ CT-Transformer |
| VAD | ✅ Silero — обрезает тишину до inference |
| Перевод | ✅ через Whisper translate task |
| Многоязычность | ✅ |

**Вывод:** Лучший баланс качества и скорости если нужен перевод.

## 📐 Архитектура пайплайна (Вариант B)

```
Входящее аудио (OGG/MP4/WAV)
        │
        ▼
  FFmpeg decode → PCM 16kHz mono
        │
        ▼
  Silero VAD    ← убирает паузы, тишину, шум
        │
        ▼ (только речевые сегменты)
  SenseVoice ASR ← ONNX, нативные C++ треды
        │
        ▼ (raw text без знаков)
  CT-Transformer ← offline punctuation
        │
        ▼
  "Привет! Как дела? Я хотел спросить..."
```

## 💡 Дополнительные идеи для проекта

### 1. VAD-предобработка (универсальная оптимизация)
Добавь Silero VAD **до** любого ASR движка. Типичное голосовое сообщение
содержит 30-50% тишины/пауз. Обрезка их до inference даёт бесплатный 2x speedup.

### 2. Очередь задач с воркерами
Вместо `asyncio.run_in_executor(None, process)` — использовать **task queue**
(Redis + BullMQ или Celery). Параллельная обработка нескольких сообщений.

### 3. Кэширование результатов
Хеш аудио (SHA256 первых 8KB) → Redis TTL 1h. Одинаковые сообщения
(forwarded) транскрибируются мгновенно.

### 4. Определение языка заранее
Sherpa-onnx имеет отдельную модель **Language ID** (~10ms). Определяй язык
сначала → передавай hint в ASR → точнее и быстрее.

### 5. Адаптивный выбор модели
- Аудио < 5 сек → SenseVoice (быстро)
- Аудио > 30 сек → faster-whisper (качество)
